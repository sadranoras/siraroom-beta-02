# پلتفرم کلاس آنلاین و کنفرانس ویدیویی (با پنل مدیریت)

یک سامانهٔ کلاس/جلسهٔ آنلاین **قابل نصب روی سرور خودتان** با ویدیو و صدای زنده، اشتراک صفحه، وایت‌بورد، چت، ضبط جلسه، نقش‌ها، پلن‌های فروش و پنل مدیریت. موتور ویدیو [LiveKit](https://livekit.io) (متن‌باز، WebRTC) است و برنامهٔ وب با **Node.js بدون هیچ وابستگی npm** نوشته شده (فقط Node 22.13 یا بالاتر).

## قابلیت‌ها

**اتاق**
- ویدیو و صدای چندنفره، نمایش گوینده فعال. **فقط کسانی که دوربینشان روشن است پنجره دارند**؛ بقیه فقط در تب «افراد» (با نشان میکروفن/دوربین) دیده می‌شوند
- اشتراک صفحه / پنجره / تب (با صدا)
- وایت‌بورد مشترک زنده (قلم، پاک‌کن، رنگ، ضخامت، بازگشت، پاک‌کردن) و همگام‌سازی برای کسانی که دیرتر وارد می‌شوند
- **ارائهٔ فایل PDF و پاورپوینت:** میزبان فایل را بارگذاری و ارائه می‌دهد، صفحه را عوض می‌کند (دکمه یا کلیدهای جهت‌دار/PageUp/PageDown/Space) و همه همان صفحه را می‌بینند. روی هر صفحه می‌توان حاشیه‌نویسی کرد؛ نوشته‌ها هر صفحه جدا نگه داشته می‌شوند و فوراً برای دانش‌آموزان نمایش داده می‌شوند
- چت متنی، «بالا بردن دست»
- دو نوع اتاق: **کلاس** (فقط میزبان/ارائه‌دهنده صحبت می‌کند) و **جلسه** (همه)
- نقش‌ها: میزبان، ارائه‌دهنده، شرکت‌کننده، مهمان
- کنترل میزبان: بی‌صدا کردن یک نفر یا همه، اجازهٔ صحبت/لغو، حذف از جلسه، پایان جلسه برای همه
- رمز اتاق، ورود مهمان بدون ثبت‌نام (قابل خاموش کردن)
- ضبط جلسه (از مرورگر میزبان، ارسال تکه‌تکه به سرور) با نشانگر «در حال ضبط» برای همه

**کاربران**
- ثبت‌نام/ورود، داشبورد (اتاق‌ها، ضبط‌ها، پلن، پرداخت‌ها، پروفایل)
- پلن‌ها: سقف تعداد اتاق، ظرفیت هر اتاق، اجازهٔ ضبط، مدت اعتبار
- خرید پلن: درگاه **زرین‌پال** یا **کارت‌به‌کارت با تأیید دستی ادمین**

**پنل مدیریت** (`/admin`)
- نمای کلی: آمار کاربران، ورود به اتاق‌ها، ساعت حضور، درآمد، حجم ضبط‌ها، نمودار ۱۴ روز، اتاق‌های زنده
- کاربران: جستجو، ساخت/ویرایش/مسدود/حذف، تغییر نقش، تخصیص پلن و انقضا
- اتاق‌ها: جستجو، باز/بستن، پایان‌دادن به جلسهٔ زنده، حذف
- پلن‌ها: ساخت/ویرایش/غیرفعال/حذف، پلن پیش‌فرض
- پرداخت‌ها: فیلتر، تأیید/رد پرداخت‌های دستی
- تنظیمات: نام برند، شعار، رنگ اصلی، فوتر، باز/بسته بودن ثبت‌نام، اطلاعات کارت

## معماری

```
مرورگر ──HTTP──▶ این برنامه (Node.js + SQLite)   ← کاربران، اتاق‌ها، پلن‌ها، پرداخت‌ها، ضبط‌ها
   │                      │ توکن ورود + API مدیریت اتاق
   └──WebRTC/WebSocket──▶ LiveKit Server               ← ویدیو، صدا، data-channel (چت/وایت‌بورد)
```

## نصب سریع (Docker)

۱. یک کلید برای LiveKit بسازید و در **هر دو** فایل `livekit.yaml` و `.env` یکسان بگذارید (`LIVEKIT_API_KEY` و `LIVEKIT_API_SECRET`؛ رمز حداقل ۳۲ کاراکتر).

۲. فایل تنظیمات را بسازید و ویرایش کنید:
```bash
cp .env.example .env
```
حداقل این‌ها را تنظیم کنید: `APP_URL`، `LIVEKIT_URL`، `LIVEKIT_API_KEY`، `LIVEKIT_API_SECRET`، `ADMIN_EMAIL`، `ADMIN_PASSWORD`.

۳. اجرا:
```bash
docker compose up -d --build
```

اگر `ADMIN_PASSWORD` را خالی بگذارید، یک رمز تصادفی ساخته و **فقط یک بار** در لاگ (`docker compose logs app`) چاپ می‌شود.

### نصب بدون Docker
```bash
# Node.js >= 22.13
cp .env.example .env     # و ویرایش
npm start
```
و LiveKit را جداگانه اجرا کنید (`livekit-server --config livekit.yaml`).

## اجرای LiveKit روی ویندوز (بدون Docker)
فایل `start-livekit.bat` را دوبار کلیک کنید. بار اول LiveKit را خودش دانلود می‌کند و با کلید و رمز فایل `.env` اجرا می‌کند. پنجره باید باز بماند. بعد `http://localhost:7880` باید `OK` نشان بدهد.

## HTTPS (الزامی)
مرورگرها بدون HTTPS اجازهٔ دوربین، میکروفن و اشتراک صفحه نمی‌دهند (به‌جز `localhost`). دو دامنه/زیردامنه با گواهی بگیرید؛ نمونه با Caddy (گواهی خودکار):

```
class.example.com {
    reverse_proxy localhost:3000
}
lk.example.com {
    reverse_proxy localhost:7880
}
```
سپس در `.env`: `APP_URL=https://class.example.com` ، `LIVEKIT_URL=wss://lk.example.com` ، `TRUST_PROXY=1`.

پورت‌های فایروال برای LiveKit: `7881/tcp` و `7882/udp` (طبق `livekit.yaml`). در شبکه‌های محدودشده ممکن است TURN لازم شود (بخش `turn` در مستندات LiveKit).

## نکتهٔ مهم برای ایران: فایل کلاینت LiveKit
صفحهٔ اتاق ابتدا `public/vendor/livekit-client.umd.min.js` را می‌خواند و اگر نبود از CDN (jsDelivr) می‌گیرد. برای اینکه به CDN وابسته نباشید، یک بار فایل را دانلود و در همان مسیر بگذارید:
```bash
curl -L -o public/vendor/livekit-client.umd.min.js \
  https://cdn.jsdelivr.net/npm/livekit-client/dist/livekit-client.umd.min.js
```

## پرداخت
- **زرین‌پال:** `ZARINPAL_MERCHANT_ID` را در `.env` بگذارید. `APP_URL` باید از اینترنت قابل دسترس باشد (آدرس بازگشت). برای تست `ZARINPAL_SANDBOX=1`.
- **کارت‌به‌کارت:** اگر مرچنت تنظیم نباشد، از «پنل مدیریت ← تنظیمات» شمارهٔ کارت را وارد کنید. کاربر شماره پیگیری ثبت می‌کند و شما در «پرداخت‌ها» تأیید می‌کنید؛ پلن بلافاصله فعال می‌شود.

## ارائهٔ فایل (PDF و پاورپوینت)
- در اتاق، دکمهٔ «📄 ارائه فایل» (فقط میزبان) ← بارگذاری ← «ارائه». ابزار قلم/پاک‌کن بالای اسلاید است. «بستن فایل» نمایش را برای همه می‌بندد.
- **PDF** مستقیم نمایش داده می‌شود (نمایشگر pdf.js داخل پروژه است و به CDN نیاز ندارد؛ مجوز Apache-2.0 در `public/vendor/PDFJS-LICENSE.txt`).
- **پاورپوینت** (`pptx, ppt, ppsx, pps, odp`) روی سرور با **LibreOffice** به PDF تبدیل می‌شود. اگر LibreOffice نصب نباشد فقط PDF پذیرفته می‌شود و پیام راهنما نشان داده می‌شود (دبیر می‌تواند در PowerPoint «Save as ← PDF» بزند).
  - نصب: اوبونتو `sudo apt install libreoffice-impress` ، ویندوز/مک: برنامهٔ LibreOffice (مسیر شناخته‌شده خودکار پیدا می‌شود، وگرنه `SOFFICE_PATH` را در `.env` بگذارید).
  - Docker: `WITH_OFFICE=1 docker compose up -d --build`
  - فونت‌های فارسی استفاده‌شده در اسلاید باید روی سرور نصب باشند، وگرنه LibreOffice جایگزین می‌کند و ظاهر ممکن است فرق کند.
- سقف حجم: `MAX_FILE_MB` (پیش‌فرض ۵۰) و حداکثر ۳۰ فایل برای هر اتاق. فایل‌ها در `data/files` ذخیره می‌شوند و با حذف اتاق یا کاربر پاک می‌شوند.
- فقط صاحب اتاق/ادمین می‌تواند فایل بارگذاری، ارائه یا حذف کند. فایل برای شرکت‌کنندهٔ اتاق با توکن امضاشدهٔ همان اتاق قابل دریافت است.

## امنیت (آنچه پیاده شده)
نقش افراد (میزبان/ارائه‌دهنده/…) فقط سمت سرور تعیین می‌شود و شرکت‌کننده نمی‌تواند خودش را میزبان جا بزند؛ پیام‌های ارائه و حاشیه‌نویسی فقط از میزبان/ارائه‌دهنده پذیرفته می‌شود. 
رمزها با scrypt هش می‌شوند؛ نشست با کوکی `HttpOnly` + `SameSite=Lax` و امضای HMAC؛ بررسی Origin روی درخواست‌های تغییردهنده؛ محدودیت تلاش ورود/ثبت‌نام/رمز اتاق؛ سربرگ‌های CSP و Permissions-Policy؛ همهٔ متن کاربر در رابط escape می‌شود؛ دسترسی اتاق/ضبط/ادمین سمت سرور کنترل می‌شود؛ توکن LiveKit مخصوص همان اتاق و با دسترسی انتشار متناسب با نقش ساخته می‌شود.

## محدودیت‌ها (صادقانه)
- این پروژه **کپی اسکای‌روم نیست**؛ کد، ظاهر و برند مستقل دارد و هستهٔ کلاس آنلاین را پوشش می‌دهد. چیزهایی که **هنوز ندارد**: نظرسنجی/آزمون درون‌جلسه، اتاق‌های گروهی (breakout)، ذخیرهٔ تاریخچهٔ چت، API/یکپارچگی LMS، اتصال تلفنی.
- تبدیل پاورپوینت فقط محتوای ثابت اسلایدها را نگه می‌دارد (انیمیشن، گذار بین اسلایدها و ویدیوی داخل اسلاید پخش نمی‌شود). فایل‌های پاورپوینت ناشناس را فقط معلمان مورد اعتماد بارگذاری می‌کنند؛ برای امنیت بیشتر سرور را در Docker اجرا کنید.
- ضبط در مرورگر **میزبان** انجام می‌شود (تب/پنجره را انتخاب می‌کند) و اگر میزبان صفحه را ببندد ضبط قطع می‌شود. برای ضبط سمت سرور و بدون وابستگی به مرورگر از LiveKit Egress استفاده کنید.
- پایگاه‌داده SQLite است (مناسب یک سرور). برای ترافیک خیلی بالا مهاجرت به PostgreSQL لازم است.
- بخش ویدیو در محیط توسعه با LiveKit **ساختگی** و مرورگر واقعی تست شد (توکن، دسترسی‌ها، رابط، وایت‌بورد، چت، نقش‌ها)، اما با سرور LiveKit واقعی و چند کاربر واقعی باید خودتان یک بار آزمایش کنید. اتصال به زرین‌پال هم بدون مرچنت واقعی قابل تست نبود.

## ساختار پروژه
```
server.js          سرور HTTP + همهٔ API ها
lib/db.js          جدول‌ها و دادهٔ اولیه (پلن‌ها)
lib/auth.js        هش رمز، توکن امضاشده، کوکی
lib/livekit.js     ساخت توکن LiveKit و فراخوانی API مدیریت اتاق (بدون SDK)
public/            صفحات: index, auth, dashboard, room, admin + wb.js (وایت‌بورد و حاشیه‌نویسی) + slides.js (نمایش فایل)
public/vendor/     pdf.js و دیکدرها/فونت‌های آن (+ فایل livekit-client که خودتان می‌گذارید)
data/              پایگاه‌داده، ضبط‌ها و فایل‌های ارائه (پشتیبان‌گیری کنید)
```
